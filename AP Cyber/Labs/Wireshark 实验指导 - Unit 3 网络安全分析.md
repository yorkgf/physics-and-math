2. 用过滤器快速定位特定协议和可疑流量

## 二、安装 Wireshark

### Windows / macOS

1. 打开浏览器访问 **[wireshark.org](https://www.wireshark.org/)**
2. 点击首页的 **Download** 按钮
3. 选择你的系统版本下载安装包
4. 安装时按默认选项一路 Next。**Windows 用户注意**：安装过程中会弹出一个叫 **Npcap** 的组件，保持默认勾选即可（它是 Wireshark 抓包的驱动）
5. 安装完成后，桌面上会出现 Wireshark 的鲨鱼图标

### 验证安装是否成功

1. 打开 Wireshark
2. 你应该能看到一个欢迎界面，左侧列出你电脑上的网络接口
3. 能看到这个界面 = 安装成功 ✅

> ⚠️ **重要提醒：本实验不需要「开始抓包」。我们只打开老师提供的 .pcap 文件做离线分析。请不要在学校网络上开启实时抓包。**

## 三、界面入门

打开 Wireshark 后，你会看到三个主要区域：

| 区域 | 位置 | 作用 |
| --- | --- | --- |
| **过滤栏** | 顶部，一个写着「Apply a display filter...」的长条 | 输入过滤条件，只显示你关心的数据包 |
| **包列表** | 上方大表格 | 每个数据包一行，显示时间、来源 IP、目标 IP、协议、长度、信息 |
| **包详情** | 中间窗格 | 点开一个包后，能看到各层协议的详细内容（以太网帧 → IP → TCP/UDP → 应用层数据） |
| **包字节** | 下方十六进制窗口 | 数据包的原始字节（进阶查看用，本实验不用深究） |

### 第一次操作：打开一个 pcap 文件

1. 从老师那儿拿到 `.pcap` 文件，保存到你电脑上
2. 在 Wireshark 里：菜单 **File → Open**，选择那个文件
3. 你会看到包列表里一下子出现几百到几千个数据包

## 四、常用过滤器（请背下来这几个）

在顶部过滤栏里输入，回车生效。

| 目的 | 过滤器 | 说明 |
| --- | --- | --- |
| 只看 ARP 包 | `arp` | 用来找 ARP 欺骗攻击 |
| 只看 DNS 包 | `dns` | 用来找 DNS 投毒/异常查询 |
| 只看 HTTP 包 | `http` | 看明文 web 请求，找 SQL 注入/XSS |
| 只看 TCP 包 | `tcp` | 看连接建立、端口扫描 |
| 只看指定 IP | `ip.addr == 10.0.0.5` | 筛选和某台机器有关的所有流量 |
| 只看指定源 IP | `ip.src == 10.0.0.100` | 从某台机器发出来的流量 |
| 只看指定目标 IP | `ip.dst == 10.0.0.1` | 发给某台机器的流量 |
| 指定端口 | `tcp.port == 80` | 80 端口的 TCP 流量 |
| 组合条件 | `arp and ip.addr == 10.0.0.1` | 同时满足两个条件 |

> 过滤器输入正确时，过滤栏背景是**绿色**；红色就是语法错了。

## 五、实验任务

请完成以下四个任务，每个任务对应一个 pcap 文件，按顺序做。

> 💡 提示：每个任务的 pcap 文件名老师会单独提供。下面用 `[文件1]` 等做占位。

### 任务 1：识别 ARP 欺骗（On-path / MITM 攻击）

**文件**：`arp-poisoning.pcap`（或老师提供的等价文件）

**背景**：在一个局域网里，10.0.0.1 是网关，10.0.0.100 和 10.0.0.200 是两台主机。攻击者通过 ARP 欺骗把自己伪装成网关，截获两台主机之间的流量。

**你要做的事**：

1. 用 `arp` 过滤器，只看 ARP 包
2. 观察不同 IP 地址对应的 **MAC 地址**
3. 找出哪台机器在撒谎——即它声称自己是某个 IP，但那个 IP 的真实 MAC 不是它

**要回答的问题**：

- 攻击者的 MAC 地址是什么？
- 攻击者冒充了哪些 IP？
- 这是哪种攻击类型？（提示：MITM / on-path attack）
- 可以用什么方法缓解？（提示：静态 ARP、动态 ARP 检测 DAI）

---

### 任务 2：识别端口扫描

**文件**：`port-scan.pcap`（或老师提供的等价文件）

**背景**：攻击者在扫描目标机器开放了哪些端口，为后续攻击做侦察（reconnaissance）。

**你要做的事**：

1. 用 `tcp.flags.syn == 1 and tcp.flags.ack == 0` 过滤所有 SYN 包
2. 看这些 SYN 包的**目标端口**是否连续变化
3. 统计在短时间内扫了多少个端口

**要回答的问题**：

- 攻击者 IP 是什么？目标 IP 是什么？
- 大约扫描了多少个端口？（只看目标端口的数量和密度）
- 这属于网络攻击的哪个阶段？（提示：侦察 / 初始访问 / 持久化…）
- 网络管理员可以用什么方法检测和阻止端口扫描？

---

### 任务 3：识别 DNS 投毒

**文件**：`dns-spoof.pcap`（或老师提供的等价文件）

**背景**：攻击者篡改了 DNS 响应，把 `bank.example.com` 的真实 IP 替换成了攻击者的恶意服务器 IP。

**你要做的事**：

1. 用 `dns` 过滤器，只看 DNS 流量
2. 找到对 `bank.example.com` 的查询（query）和响应（response）
3. 看响应里返回的 IP 地址是否合理
4. 对比同时刻对其他域名的响应，找出异常

**要回答的问题**：

- `bank.example.com` 在 DNS 响应中被解析到了哪个 IP？
- 这个 IP 和同一家公司其他域名所在的网段一致吗？
- 用户点击恶意链接后，可能发生什么？（提示：凭证窃取 credential harvesting）
- 企业可以用什么防护手段？（提示：DNSSEC、可信 DNS 解析器）

---

### 任务 4：综合分析 — 从日志到报告

**文件**：`composite-attack.pcap`（或老师提供的等价文件）

**背景**：一家医院的网络发生了一起攻击。作为网络安全分析师，你需要完整还原攻击过程。

**你要做的事**：

1. 先整体浏览一遍（不加过滤器），观察有哪些协议、哪些 IP 在活跃
2. 逐步过滤：先看 `arp` → 再看 `tcp.port == 22 or tcp.port == 3389` → 再看 `http`
3. 按时间线还原攻击步骤

**最终产出：一份简短安全报告，包含**：

- 攻击时间线（每一步发生了什么）
- 识别出的攻击类型列表
- 攻击者使用的 IP / MAC / 端口
- 受影响的资产
- 至少 3 条缓解建议（分层防护 defense-in-depth）

## 七、常见问题

**Q：打开 pcap 后，包列表全是英文缩写，看不懂怎么办？**
A：先看 Protocol 列和 Info 列。Protocol 告诉你是什么协议（ARP/DNS/TCP/HTTP…），Info 列用一句话概括了这个包在干什么。如果还看不懂，告诉老师你卡在哪。

**Q：过滤器输了没反应？**
A：检查过滤栏背景色——绿色=生效，红色=语法错。确认拼写和大小写（Wireshark 过滤器不区分大小写，但 `==` 是两个等号，别写成一个）。

**Q：几千个包，我应该从哪看起？**
A：从最前面（时间最早）的包开始，先整体扫一遍协议分布，再用过滤器缩小范围。任务 1–3 已经给了你过滤器提示。

**Q：我可以用 AI 工具帮忙吗？**
A：本实验**不允许**用 AI 来完成分析任务。AI 只能在你做完之后，用来检查你对概念的理解是否准确——但结论要自己想。
