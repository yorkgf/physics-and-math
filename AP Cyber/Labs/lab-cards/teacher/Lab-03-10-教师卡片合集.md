## Lab 03: SQL注入攻击与防御

### 基本信息

| 项目 | 内容 |
|-----|------|
| 实验编号 | Lab 03 |
| 实验名称 | SQL注入攻击与防御 |
| 对应单元 | Unit 5: Securing Applications and Data |
| 学习目标 | 5.1.B, 5.5.B |
| 时长 | 30分钟 |
| 难度 | ★★☆ |

### 教学目标

**知识目标：**
1. 理解SQL注入攻击的原理
2. 掌握SQL注入的常见类型
3. 理解输入验证和参数化查询的防御方法

**技能目标：**
1. 能够执行基础的SQL注入攻击
2. 能够分析SQL注入漏洞的代码
3. 能够编写安全的SQL查询

### 实验步骤详解

**第一阶段：理解SQL注入（5分钟）**

教师讲解：
1. SQL注入的定义
2. 攻击原理演示
3. 常见注入点

**SQL注入原理图：**

```
正常查询：
SELECT * FROM users WHERE id = '1'

注入后：
SELECT * FROM users WHERE id = '1' OR '1'='1'
```

**第二阶段：Low安全级别攻击（15分钟）**

教师演示：
1. 进入 SQL Injection 模块
2. 输入正常ID：`1`
3. 尝试注入payload

**学生操作：**

| Payload | 预期结果 | 实际结果 |
|---------|---------|---------|
| `1` | 返回用户1信息 | |
| `1' OR '1'='1` | 返回所有用户 | |
| `1' OR '1'='1' --` | 返回所有用户 | |
| `1' UNION SELECT null, null --` | 尝试联合查询 | |
| `1' UNION SELECT null, version() --` | 获取数据库版本 | |

**第三阶段：分析注入原理（5分钟）**

教师引导：
1. 分析SQL查询结构
2. 解释注入如何改变查询逻辑
3. 讨论不同注入类型

**注入类型：**

| 类型 | 描述 | 示例 |
|-----|------|-----|
| 布尔注入 | 利用真假条件 | `' OR '1'='1` |
| 联合查询 | 合并多个查询 | `UNION SELECT` |
| 报错注入 | 利用错误信息 | `AND extractvalue` |
| 时间盲注 | 利用延时 | `AND sleep(5)` |

**第四阶段：防御措施分析（5分钟）**

教师讲解：
1. 输入验证
2. 参数化查询
3. 存储过程
4. 最小权限原则

**安全代码示例：**

```php
// 不安全的代码
$query = "SELECT * FROM users WHERE id = '$id'";

// 安全的代码（参数化查询）
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = ?");
$stmt->execute([$id]);
```

### 预期答案

**SQL注入原理：**
- 攻击者通过在输入字段中插入SQL代码
- 这些代码会被服务器当作SQL命令执行
- 可以绕过认证、读取数据、修改数据

**防御措施：**
1. 使用参数化查询（最有效）
2. 输入验证和过滤
3. 使用ORM框架
4. 最小权限原则
5. 错误信息不显示SQL细节

### 常见问题

| 问题 | 解答 |
|-----|------|
| SQL注入能做什么？ | 读取、修改、删除数据，甚至控制服务器 |
| 为什么参数化查询有效？ | 将数据和代码分离，防止代码注入 |
| 如何发现SQL注入？ | 输入特殊字符观察响应，使用自动化工具 |

3. 掌握XSS攻击的检测和防御方法

**技能目标：**

### 实验步骤详解

**第一阶段：理解XSS（5分钟）**

教师讲解：
1. XSS的定义
2. 攻击原理
3. XSS类型

**XSS类型对比：**

| 特征 | 反射型XSS | 存储型XSS | DOM型XSS |
|-----|----------|----------|----------|
| 持久性 | 非持久 | 持久 | 非持久 |
| 存储位置 | URL | 服务器 | 客户端 |
| 触发方式 | 点击链接 | 访问页面 | 修改DOM |

**第二阶段：反射型XSS攻击（10分钟）**

教师演示：
1. 进入 XSS (Reflected) 模块
2. 输入正常文本
3. 尝试XSS payload

**学生操作：**

| Payload | 预期结果 | 实际结果 |
|---------|---------|---------|
| `test` | 显示test | |
| `<script>alert('XSS')</script>` | 弹窗 | |
| `<img src="x" onerror="alert('XSS')">` | 弹窗 | |
| `<svg onload="alert('XSS')">` | 弹窗 | |

**第三阶段：存储型XSS攻击（10分钟）**

教师演示：
1. 进入 XSS (Stored) 模块
2. 在Guestbook中输入XSS payload
3. 刷新页面观察效果

**学生操作：**
1. 输入：`<script>alert('Stored XSS')</script>`
2. 提交后刷新页面
3. 观察是否持续有效

**第四阶段：防御措施分析（5分钟）**

教师讲解：
1. 输出编码
2. 内容安全策略(CSP)
3. 输入验证
4. HttpOnly Cookie

**防御代码示例：**

```php
// 不安全的代码
echo $user_input;

// 安全的代码（输出编码）
echo htmlspecialchars($user_input, ENT_QUOTES, 'UTF-8');
```

### 预期答案

**XSS攻击原理：**
- 攻击者在网页中注入恶意脚本
- 当其他用户访问该页面时，脚本会在其浏览器中执行
- 可以窃取Cookie、会话令牌、个人信息

**反射型vs存储型XSS：**
- 反射型：payload在URL中，需要诱导点击
- 存储型：payload存储在服务器，所有访问者都会受影响
- 存储型更危险，因为影响范围更广

**防御措施：**
1. 对所有输出进行HTML编码
2. 实施内容安全策略(CSP)
3. 设置Cookie为HttpOnly
4. 输入验证和过滤

| 时长 | 30分钟 |
| 难度 | ★★☆ |

### 教学目标

**知识目标：**
1. 理解CSRF攻击的原理
2. 识别CSRF攻击的特征
3. 掌握CSRF防护机制

**技能目标：**
1. 能够构造CSRF攻击
2. 能够分析CSRF漏洞
3. 能够实施CSRF防护

### 实验步骤详解

**第一阶段：理解CSRF（5分钟）**

教师讲解：
1. CSRF的定义
2. 攻击原理
3. 攻击流程图

**CSRF攻击流程：**

```
用户登录网站 → 攻击者诱导点击 → 浏览器自动发送请求 → 服务器执行操作
```

**第二阶段：构造CSRF攻击（10分钟）**

教师演示：
1. 进入 CSRF 模块
2. 分析密码修改功能
3. 构造恶意链接

**学生任务：**
1. 创建包含恶意链接的HTML文件：

```html
<html>
<body>
  <h1>点击领取奖品！</h1>
  <a href="http://192.168.0.169/vulnerabilities/csrf/?password_new=hacked&password_conf=hacked&Change=Change">
    点击这里
  </a>
</body>
</html>
```

2. 保存为 `csrf_attack.html`
3. 诱导同学点击（模拟攻击）

**第三阶段：分析CSRF原理（10分钟）**

教师引导：
1. 分析为什么攻击会成功
2. 讨论CSRF与XSS的区别
3. 分析CSRF的危害

**CSRF vs XSS对比：**

| 特征 | CSRF | XSS |
|-----|------|-----|
| 攻击目标 | 执行操作 | 窃取信息 |
| 依赖条件 | 用户已登录 | 页面存在漏洞 |
| 攻击方式 | 伪造请求 | 注入脚本 |

**第四阶段：防御措施分析（5分钟）**

教师讲解：
1. CSRF Token
2. SameSite Cookie
3. 验证Referer
4. 要求重新认证

**CSRF Token原理：**

```
服务器生成Token → 嵌入表单 → 提交时验证Token → 防止伪造请求
```

### 预期答案

**CSRF攻击原理：**
- 利用用户已登录的状态
- 诱导用户点击恶意链接
- 浏览器自动携带Cookie发送请求
- 服务器无法区分正常请求和伪造请求

**防御措施：**
1. 使用CSRF Token（最有效）
2. 设置Cookie的SameSite属性
3. 验证HTTP Referer头
4. 敏感操作要求重新认证

### 基本信息

| 项目 | 内容 |

### 教学目标

**知识目标：**
1. 理解命令注入攻击的原理
2. 识别命令注入漏洞的特征
3. 掌握命令注入的防御方法

**技能目标：**
1. 能够执行命令注入攻击
2. 能够分析命令注入漏洞
3. 能够实施命令注入防御

### 实验步骤详解

**第一阶段：理解命令注入（5分钟）**

教师讲解：
1. 命令注入的定义
2. 攻击原理
3. 常见注入点

**命令连接符：**

| 符号 | 功能 | 示例 |
|-----|------|-----|
| `&&` | 前一个成功才执行后一个 | `cmd1 && cmd2` |
| `\|\|` | 前一个失败才执行后一个 | `cmd1 \|\| cmd2` |
| `;` | 顺序执行 | `cmd1 ; cmd2` |
| `\|` | 管道 | `cmd1 \| cmd2` |

**第二阶段：Low安全级别攻击（10分钟）**

教师演示：
1. 进入 Command Injection 模块
2. 输入正常IP地址
3. 尝试命令注入

**学生操作：**

| Payload | 功能 | 预期结果 | 实际结果 |
|--------|------|---------|---------|
| `127.0.0.1` | 正常ping | | |
| `127.0.0.1 && whoami` | 执行whoami | | |
| `127.0.0.1 \|\| ls` | 列出文件 | | |
| `127.0.0.1 ; cat /etc/passwd` | 读取密码文件 | | |
| `127.0.0.1 \| id` | 获取用户ID | | |

**第三阶段：分析命令注入原理（10分钟）**

教师引导：
1. 分析命令执行流程
2. 解释命令连接符的作用
3. 讨论命令注入的危害

**命令注入流程图：**

```
用户输入 → 拼接到系统命令 → 执行命令 → 返回结果
     ↓
  恶意输入 → 改变命令逻辑 → 执行恶意命令
```

**第四阶段：防御措施分析（5分钟）**

教师讲解：
1. 输入验证
2. 使用安全API
3. 最小权限原则
4. 命令白名单

**安全代码示例：**

```php
// 不安全的代码
system("ping " . $ip);

// 安全的代码（使用escapeshellarg）
system("ping " . escapeshellarg($ip));
```

### 预期答案

**命令注入原理：**
- 应用将用户输入拼接到系统命令中
- 攻击者通过特殊字符改变命令逻辑
- 系统执行攻击者注入的命令

**防御措施：**
1. 避免调用系统命令，使用语言内置API
2. 如果必须调用，使用escapeshellarg/escapeshellcmd
3. 输入验证，只允许合法字符
4. 最小权限原则，限制执行权限

|-----|------|-----|

| 错误日志 | 错误和异常 | 排查问题 |
| 认证日志 | 登录记录 | 检测暴力破解 |
| 应用日志 | 应用操作记录 | 审计追踪 |

**第二阶段：执行攻击生成日志（10分钟）**

教师演示：

**学生操作：**

2. 执行XSS攻击：`<script>alert('XSS')</script>`

4. 记录所有攻击

**第三阶段：分析攻击日志（10分钟）**

教师演示：
1. 访问日志文件
2. 识别攻击请求
3. 分析攻击特征

**攻击日志特征：**

| 攻击类型 | 日志特征 | 示例 |
|---------|---------|------|

| XSS | 包含HTML/JS标签 | `<script>`, `onerror` |
| 命令注入 | 包含命令连接符 | `&&`, `\|\|`, `;` |
| 目录遍历 | 包含路径遍历 | `../`, `..\\` |

**第四阶段：创建检测规则（5分钟）**

```
# SQL注入检测

# XSS检测

# 命令注入检测

```
